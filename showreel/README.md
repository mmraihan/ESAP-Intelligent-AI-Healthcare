# ESAP Clinical AI — 60-second showreel

Motion-graphics product video (16:9 1920×1080 and 9:16 1080×1920, 30 fps, 60 s) built as code:
an HTML/JS timeline where **every frame is a pure function of time** (`window.seek(t)`), rendered
frame-by-frame with headless Chromium and encoded with ffmpeg. The score is synthesised with numpy/scipy.

| File | Purpose |
|---|---|
| `out/ESAP-Clinical-AI-showreel-16x9.mp4` | Final 16:9 cut (with music) |
| `out/ESAP-Clinical-AI-showreel-9x16.mp4` | Final 9:16 cut (with music) |
| `out/music.wav` | The synthesised score (regenerated by `music.py`, not committed) |
| `index.html`, `reel.js` | The timeline / all scenes (landscape + portrait layouts: `?a=16x9` / `?a=9x16`) |
| `music.py` | Music synthesis, locked to the timeline (120 BPM, drop at 10.0 s) |
| `render.mjs` | Parallel frame renderer + ffmpeg mux |
| `assets/ui/` | Screens captured from the product (see below) |
| `assets/logo.svg` | The ESAP logo (copied from `system-final-v/frontend/public/favicon.svg`) |

## Rebuild

```bash
cd showreel
npm i                                           # playwright-core only; uses the system Chromium
python3 -m venv .venv && .venv/bin/pip install numpy scipy
.venv/bin/python music.py                       # -> out/music.wav
node render.mjs 16x9 && node render.mjs 9x16    # -> out/*.mp4   (CHROME=/path/to/chrome to override)
```

## Where the product footage came from

`care.esap.ai` (and the Vercel mirror) were **not reachable from the cloud sandbox this was built in**
(egress policy denied both hosts). The screens were therefore captured from the same product built from
this repository (`system-final-v/`, run locally with the guide in `ROLE_AND_TESTING_GUIDE.md`), using the
same fictional demo accounts and seed data, with Playwright at 1920×1080 @2× (desktop) and 412×892 @2–3× (phone).
Nothing was submitted, changed or deleted — screens were only opened and photographed.

Treatments applied to the captured pixels (documented so nothing is hidden):

* login e-mail addresses in the audit log / roster were masked (`••••••@••••••`);
* red / amber / green accent colours in the UI were remapped to the blue-teal brand scale
  (the brand rule is "no traffic-light colours"); the UI's text and layout are untouched;
* the "Why?" panel is only shown cropped to its bar section (its footer carries a developer
  "stub model" note that does not belong in a promo).
